# Ship an MDX directory as a static documentation site

Doctrine turns MDX files and colocated navigation metadata into prerendered HTML, a hydrated React
interface, and a Pagefind search index. Development runs through Vite; production output is ordinary
static files.

```sh
pnpm add @amamo/doctrine
pnpm exec doctrine dev docs
```

<Callout variant="tip" title="Static output, executable input">
  Register React components once and use them in any MDX document. The deployed `dist` directory
  needs no Node.js server, but the build must only process MDX, config, and component code you
  trust.
</Callout>

## From source to site

```text
MDX + meta.ts + doctrine.config.ts
  -> config and navigation normalization
  -> @amamo/mdx content compilation
  -> Vite client and SSR bundles
  -> React prerender for every navigation route
  -> HTML + assets + 404.html
  -> Pagefind index from the final HTML
```

The same runtime shell renders development requests, production pages, and client hydration. Routes,
locale links, custom components, and theme behavior therefore share one implementation.

## What Doctrine owns

- Vite SSR development with MDX and navigation watching
- strict production navigation validation
- route generation from directories, page basenames, and locale suffixes
- localized titles, descriptions, canonical URLs, and alternate links
- lazy development search and a production Pagefind index
- responsive navigation, search, GitHub link, locale switcher, and persistent theme
- custom CSS and React component registration
- deployment bases for repository subpaths

## What you provide

The smallest site has one document and one navigation file:

```text
docs/
├── index.mdx
└── meta.ts
```

`docs/index.mdx` maps to `/`. A nested `docs/guide/install.mdx` maps to `/guide/install/`, provided
the root and nested `meta.ts` files include that directory and page. Production builds reject missing,
duplicate, or nonexistent navigation entries.

Doctrine depends on the native `@amamo/mdx` compiler. Use Node.js 20.19 or newer on a
[supported target](https://jikkai.github.io/mdx/native-targets/); there is no JavaScript fallback.
