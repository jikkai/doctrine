# Ship documentation from an MDX directory

Doctrine gives an MDX directory a development server, static HTML, client hydration, search,
localization, themes, and a responsive documentation shell. You provide content and optional React
components; Doctrine owns the site pipeline.

```sh
pnpm add @amamo/doctrine
pnpm exec doctrine dev docs
```

[Build your first site](/guide/getting-started/) in a few minutes, then review the
[feature set](/features/) and [configuration reference](/configuration/).

<Callout>
  Register React components once and use them in any MDX document. Doctrine builds plain static
  files, so you can deploy `dist` to GitHub Pages or any static host without a production Node.js
  server.
</Callout>

## What Doctrine includes

- Vite SSR during development and static generation for production
- MDX compilation and filename conventions from `@amamo/mdx`
- Pagefind full-text search generated from the final HTML
- Locale-aware routes, metadata, navigation, and language switching
- Persistent light and dark themes without an initial color flash
- Custom React components shared by SSR and client hydration
- Correct assets, links, search results, canonical URLs, and 404 pages under a deployment subpath

## What you provide

At minimum, create one `.mdx` file and a colocated `meta.ts` navigation file. Add
`doctrine.config.ts` only when you need site metadata, localization, icons, a custom output
directory, or custom components.

```text
docs/
├── index.mdx
├── meta.ts
└── guide/
    ├── install.mdx
    └── meta.ts
```

The file tree becomes the route tree: `docs/index.mdx` is `/`, and
`docs/guide/install.mdx` is `/guide/install/`.
