# 把 MDX 目录发布成静态文档网站

Doctrine 将 MDX 文件和就近的导航元数据转换成预渲染 HTML、可 hydration 的 React 界面和
Pagefind 搜索索引。开发环境由 Vite 驱动；生产产物是普通静态文件。

```sh
pnpm add @amamo/doctrine
pnpm exec doctrine dev docs
```

<Callout variant="tip" title="静态产物，可执行输入">
  React 组件只需注册一次，就能在任意 MDX 文档中使用。部署后的 `dist` 不需要 Node.js
  服务器，但构建只能处理你信任的 MDX、配置和组件代码。
</Callout>

## 从源码到网站

```text
MDX + meta.ts + doctrine.config.ts
  -> 归一化配置与导航
  -> @amamo/mdx 编译内容
  -> Vite 生成客户端和 SSR bundle
  -> React 预渲染每条导航路由
  -> HTML + 资源 + 404.html
  -> Pagefind 索引最终 HTML
```

开发请求、生产页面和客户端 hydration 使用同一个运行时外壳，因此路由、语言链接、自定义
组件和主题行为共用一套实现。

## Doctrine 负责什么

- 带 MDX 与导航监听的 Vite SSR 开发服务器
- 严格的生产导航校验
- 根据目录、页面 basename 和 locale 后缀生成路由
- 本地化 title、description、canonical URL 和 alternate 链接
- 惰性开发搜索与生产 Pagefind 索引
- 响应式导航、搜索、GitHub 链接、语言切换和持久化主题
- 自定义 CSS 与 React 组件注册
- GitHub Pages 等仓库子路径的部署 base

## 你需要提供什么

最小网站只有一篇文档和一份导航文件：

```text
docs/
├── index.mdx
└── meta.ts
```

`docs/index.mdx` 对应 `/`。嵌套的 `docs/guide/install.mdx` 对应 `/guide/install/`，前提是根目录
和子目录的 `meta.ts` 都包含对应目录与页面。生产构建会拒绝遗漏、重复或不存在的导航条目。

Doctrine 依赖原生 `@amamo/mdx` 编译器。请在[受支持目标](https://jikkai.github.io/mdx/native-targets/)
上使用 Node.js 20.19 或更新版本；它没有 JavaScript fallback。
